# P2.5 — the standard serializer's public surface

## Decision (PROPOSED)

> This record is the agent's **proposed** disposition, offered for the owner to
> ratify, reject, or adjust. Nothing here is binding until the owner merges it
> (P0.1 §4).

### 1. OUT-O2 — the entry point is `serialize_url(x, standard=, form=)`

One export, not two. The standard is a **value**, not a function name:

```r
serialize_url(url, standard = c("whatwg", "rfc3986"),
              form = c("source", "normalized"), engine = NULL)
```

This is P2.2 Q1's own working name and its recommendation, and it matches the
`url_standard` selector idiom ADR 0007 established: rurl already spells "which
standard" as an argument everywhere else, so spelling it as a function name here
would make the FSSS the one place the vocabulary breaks. Splitting into
`serialize_whatwg()` / `serialize_rfc()` would also double the surface a caller
must dispatch over when the standard is chosen at runtime, which is the normal
case for a conformance harness.

A `standard =` argument on an **existing accessor** is rejected: every accessor
returns a *component*, and (b) returns the whole string. Attaching it to
`get_clean_url()` in particular would be the C-04 conflation stated as an API.

`standard` has a default (`"whatwg"`) rather than being required. WHATWG is the
web's live standard and the profile most callers want; requiring the argument
buys strictness the rest of the API does not ask for. This is **not** an
ADR 0007 "default flip": `url_standard = NULL` is untouched, and `NULL` is not a
legal `standard` here because a serializer with no standard has nothing to
serialize to.

### 2. OUT-O3 — both RFC postures are exposed, as `form =`

`form = "source"` (default) is RFC 3986 §5.3 recomposition with **no**
normalization: source bytes survive and the undivided `userinfo` slice is
emitted verbatim. `form = "normalized"` adds §6.2.2 syntax-based normalization
(scheme/host case, percent-triplet case and unreserved-octet decoding, path
segment normalization) plus §6.2.3 default-port elision.

Both, because choosing one forfeits something P5.3 needs:

- only `source` can serve the **round-trip oracle** — byte reproduction of an
  already-conformant input is a strictly stronger property than idempotence, and
  it is unobservable if the serializer normalizes;
- only `normalized` can serve as a **comparison substrate** — an oracle's
  expected value is normalized, so scoring against `source` would score
  spelling, not conformance.

`form` is ignored under `standard = "whatwg"`, whose serializer has one
spec-defined form. This is documented rather than made an error, so a harness
can sweep both standards with one call shape.

`form` is **not** a presentation dial and does not breach C-05. It selects which
of two *standard-defined* renderings of the parsed state is wanted; both are
identities, and neither is reachable by any cleaning knob.

### 3. The parse posture the surface serializes from

A serializer serializes a parse. Which parse was not covered by any accepted
record, and the answer is load-bearing, so it is fixed here: each standard is
parsed under **its own** shipped profile — `whatwg` for `standard = "whatwg"`,
`rfc-syntax` for `standard = "rfc3986"` (both `form`s). Both carry
`scheme_acceptance = "general"` and `scheme_policy = "require"`.

Two consequences are deliberate:

- **Any scheme is accepted.** A standard serializer restricted to rurl's
  http/https/ftp web subset could not serialize `mailto:` or `urn:`, which both
  standards define.
- **A scheme is required.** Neither standard defines a base-URL-free parse of
  `example.com/x`. rurl's `https://` prepend is browser-*like* fix-up and is
  surface (c)'s business; letting it reach a standard serialization would make
  the FSSS assert conformance for a string the standard rejects. Scheme-less
  input returns `NA`.

### 4. The host spelling WHATWG's serializer emits

WHATWG's host parser produces the **ASCII (punycode) domain**, so the FSSS emits
it. `clean_url` keeps the Unicode spelling (`host_encoding = "keep"`), because
readability is a cleaning concern.

This is recorded because it is the first place surfaces (b) and (c) visibly
disagree on a non-credential, non-fragment input: `http://ПРИВЕТ.рф/A` is
`http://xn--b1agh1afp.xn--p1ai/A` on (b) and `http://ПРИВЕТ.рф/A` on (c). Both
are correct for their surface. Any harness that treated the two as
interchangeable was measuring the wrong one (RURL-yeikpnan).

The default-port elision is likewise a **parse** fact, not a serializer policy:
WHATWG's parser nulls a port equal to the scheme's default, so the record carries
no default port and the serializer emits whatever it is handed. RFC `source`
keeps it; `normalized` elides it under §6.2.3.

## Rationale

The FSSS contract was fully SETTLED except for its name and one posture, and both
gaps were explicitly routed to "the surface-b build slice" — this one. Settling
them here rather than in a later record keeps the rule P2.2 set: the surface,
the contract, and the API spelling are decided by records, and the code
instantiates them.

The three-way split in §1–§2 (name / posture / form-is-not-a-dial) matters
because the pressure on this surface will always be to add one more knob. C-05
is easy to state and easy to erode one "just this one" at a time. Naming `form`
as a standard-selector and pinning the signature executably (a test reads
`formals(serialize_url)`) makes the next such addition fail a test rather than
pass a review.

## Consequences

### The WHATWG credential ruling is lossy, and that is spec-exactness

WHATWG appends credentials only when the username or password is non-empty, so
`http://@h/` serializes as `http://h/` and `http://u:@h/` as `http://u@h/`, both
WPT-pinned. This reads as tension with the contract line calling surface (b)
"credential-complete".

It is resolved toward spec-exactness, per the standing owner mandate that
standards conformance beats preserving old output. Completeness is a property of
the **record**, which keeps the undivided userinfo slice; the undivided spelling
*is* rendered verbatim by the RFC `source` posture, which has no credential
concept to be exact about. **The owner has been told and has not objected, but
has not explicitly ruled.** If the contract line is read as binding on *output*
rather than on the record, the WHATWG half needs revisiting and this consequence
is the place to reopen.

### Adding this export still reopens G3 — P0.6's split missed a pin

P0.6 moved the surface **roster** out of G3's `## Inputs` so that surface growth
would stop forcing a re-acceptance. This export is the first surface growth since
that split, and it was measured before and after in strict mode. The result:

- the roster (`public-surface-disposition.md`) behaved exactly as P0.6 designed —
  it took its new row, is manifest-pinned, and drifted no gate input;
- but `registers/public-surface-inventory.md` also takes one row per export, and
  it **is** hashed in the `## Inputs` of `public-surface-closure.md`, which P0.6
  deliberately kept as a G3 pin.

So the cascade P0.6's own comment says it removed is still live, one link over:
inventory register → closure invariant → cross-artifact capstone → G3 acceptance.
Measured: adding `serialize_url` moves `public-surface-closure.md` from
`9a1cd6c68141` to `9bc15ab8a73a`, and the capstone from `4931bde27370` to
`8d65d516d715` — and those two *former* values are exactly what the pending
`G3-acceptance-3` (PR #286) pins. G3 reopens on pure surface growth.

Those two numbers are the measurement **isolated to the export**, taken before
this record's own contract edits were applied. The files moved again afterwards
for an unrelated and legitimate reason (settling OUT-O2/OUT-O3 changes
`output-contracts.md`, which *should* reopen G3), so their current values differ.
The isolated measurement is the one that bears on P0.6's claim.

This is a finding about the control plane, not about this surface, and it is
**not** fixed here — sweeping a gate hash is forbidden and widening P0.6's split
is P0.6's own business. It is recorded so the next three queued surfaces
(`RURL-mihbyjsr` key/join, 8 exports; `RURL-nyjnplyh` `format_url`) do not each
rediscover it.

### The evidence re-baseline is now unblocked and is not optional

Every conformance and benchmark harness in the repo scores against `clean_url`,
which P5.3 CLAIM-1 does not admit as a claim substrate. Until this export
existed there was no admissible substrate to score against. There is now, and
`RURL-yeikpnan` carries the re-baseline — in **one** pass, per the owner's
instruction, never piecemeal.

## Open questions for the owner

1. **Is the WHATWG credential ruling right?** See Consequences above. The
   alternative reading — "credential-complete" binds on output — would require
   the WHATWG serializer to emit a bare `@`, which no WPT vector expects.
   *Recommendation:* keep spec-exactness; the record carries the losslessness.
2. **Should `standard` default, or be required?** This record defaults it to
   `"whatwg"`. *Recommendation:* keep the default; a required argument makes
   every call site noisier for no conformance gain.
3. **`urn:ietf:rfc:2648` is `NA` under `rfc3986` but serializes under `whatwg`.**
   This is pre-existing `rfc-syntax` parser behavior, not introduced here, and it
   looks wrong — `path-rootless` admits colons. *Recommendation:* file it against
   the parser rather than compensate in the serializer, and let the
   `RURL-yeikpnan` re-baseline size it.

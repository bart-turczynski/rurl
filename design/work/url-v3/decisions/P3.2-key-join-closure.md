# P3.2 — v3 key/join closure (KJ-O1..KJ-O8)

## Decision (PROPOSED)

> **Proposed, not binding.** This record is authored by the agent at
> `state: PROPOSED`. It becomes authoritative only when the owner
> (`github:bart-turczynski`) merges it, at which point the seal procedure
> (P0.1 §Ratification) stamps `ACCEPTED`. Until then nothing here is normative;
> it is the agent's proposed closure of the eight `KJ-O*` open cells for the
> owner to ratify or adjust. The frontmatter reads `PROPOSED` and
> `accepted_at: pending` because the record never claims an approval that does
> not yet exist.

Accepted **P3.1** fixed the v3 comparison-key contract, the versioned key
policy, the scheme/port truth tables, and the six-join semantics
(`decisions/P3.1-identity-canonical-join.md`). When G3.K projected P3.1 and the
frozen S5 evidence into the normative key/join contract, it found **eight exact
cells P3.1 did not choose a branch on** — several because S5 itself offered a
fork P3.1 never selected, several because S5 marked owner confirmation required.
G3.K recorded them as explicit OPEN rows `KJ-O1..KJ-O8` rather than filling them
by invention (`contracts/key-join-contracts.md:212-253`). This record is their
single compact closure, so no dangling cell propagates into G3.7 or the G3.X
capstone. Each decision below cites the exact `KJ-O*` cell it closes.

### D-A. KJ-O1 — default parsing standard for `url_key_policy()`

**Decision: `"whatwg"`.** P3.1 D-B requires an explicit standard field with a
stable owner-selected default but names none (`KJ-O1`,
`contracts/key-join-contracts.md:218-221`). The default is `"whatwg"`, not the
shipped `parse_url()` default of `NULL`. The comparison-key surface
(`get_url_key()` / `url_key_policy()` / the six joins) is **new** in v3 with no
persisted keys and no back-compat debt, so the owner mandate that standards
conformance beats preserving old output applies cleanly: the key is anchored to
a named standard's identity semantics rather than to `NULL`'s
infer-a-scheme heuristic. `NULL` and `"rfc3986"` remain selectable policy
values; only the **default** is fixed here. Because the default is part of the
key policy, choosing it bumps nothing retroactively (there are no v2 keys) and a
future default change would bump the key version per P3.1 D-B.

### D-B. KJ-O2 — trailing-root-dot domain equivalence

**Decision: DISTINCT by default.** Under the default (exact) key policy,
`example.com.` does **not** compare equal to `example.com`; the terminal DNS
root dot is key-significant (`KJ-O2`,
`contracts/key-join-contracts.md:222-226`).

Rationale — this reverses the agent's initial "equal" recommendation on
spec-exact grounds. WHATWG URL equality is defined as comparison of **serialized
URLs**; the standard singles out **certificate comparison** — not general URL
equivalence — as the context that ignores a trailing dot in the host. Treating
`example.com.` and `example.com` as equal would therefore be an explicit
DNS-resolution-oriented relaxation, not the spec-exact baseline, and P3.1's key
compares the internal normalized domain identity "before presentation," which
does not license discarding an observed label. If product demand later justifies
root-dot collapse, it is added as an **explicit, versioned DNS-oriented
comparison-policy value** (a key-version bump per P3.1 D-B), never as a silent
default. This distinction is coordinated with **G3.H**, which owns the host
identity vocabulary and must record the root dot as a retained, key-significant
part of normalized domain identity.

### D-C. KJ-O3 — `url_right_join()` stable order

**Decision: the y-primary mirror of `url_left_join()`.** P3.1 adopts an
independent rurl contract but does not choose between the S5 fork of a y-primary
mirror and another pinned order (`KJ-O3`,
`contracts/key-join-contracts.md:227-230`). The pinned algorithm is: emit every
`y` row in `y` order; within each `y` row expand eligible `x` matches in `x`
match order; unmatched `y` rows receive the missing-`x` payload. This is the
exact reflection of the settled `url_left_join()` order (x-primary, y-expansion
in y order), so the two directional joins are defined by one symmetry rather than
two independent order rules, and fixtures can be derived by swapping sides.

### D-D. KJ-O4 — non-keyable `x` rows in `url_anti_join()`

**Decision: retained as unmatched (kept in the result).** S5 recommends
retaining non-keyable `x` rows but marks owner confirmation required, and P3.1
does not confirm it (`KJ-O4`, `contracts/key-join-contracts.md:231-234`). A
non-keyable `x` row has, by construction, **no eligible `y` match** — which is
exactly the anti-join membership predicate ("each `x` row with no eligible `y`
match"). Dropping it would silently conflate "not keyable" with "matched and
therefore excluded," the class of silent-row-loss defect P3.1 D-C/D-D exists to
prevent. Non-keyable `x` rows are therefore **kept**, consistent with the
never-match default for missing/non-keyable rows in P3.1 D-C.

### D-E. KJ-O5 — public URL-column selector signature

**Decision: a single `by` argument using the named-vector idiom; no separate
`col_x`/`col_y`.** P3.1 fixes one URL column per side for the first release but
not the public formals (`KJ-O5`, `contracts/key-join-contracts.md:235-238`). The
public signature exposes `by` alone: a bare string names one column present on
both sides; a length-one **named vector** maps left to right,
`by = c(x_col = "y_col")` (name = the `x` column, value = the `y` column). This
is a familiar, discoverable idiom, and it extends to multi-column keying later
**without a signature break** (a longer named vector), whereas paired
`col_x`/`col_y` scalars would need a new argument to generalize. G3.4 records the
resulting exports.

### D-F. KJ-O6 — suffix and duplicate-name repair

**Decision: a single deterministic rurl repair algorithm with
`suffix = c(".x", ".y")` as the default; ambiguity is an early error, never a
silent repair.** P3.1 requires deterministic behavior and early rejection of
ambiguity but does not choose the algorithm (`KJ-O6`,
`contracts/key-join-contracts.md:239-243`). The algorithm is defined as an
**independent rurl contract** (not "dplyr-compatible" — no unspecified external
behavior is inherited):

1. Each side's input column names must be **unique**; a side with duplicate
   input names is an error before any join work.
2. `suffix` must be a length-2 vector of **non-`NA` scalar strings**; otherwise
   an error.
3. Suffixing applies **deterministically** to the set of non-key columns whose
   names overlap between the two sides: the `x` occurrence gains `suffix[[1]]`,
   the `y` occurrence gains `suffix[[2]]`.
4. If applying the requested suffixes — against each other or against any
   existing (non-overlapping) column name — cannot produce a **unique** output
   schema, it is an **early error**. Columns are **never** silently repaired,
   renamed beyond the defined suffixing, or dropped.

### D-G. KJ-O7 — comparison-key visibility default

**Decision: hidden by default; opt-in exposure via `key_name = NULL`.** P3.1
requires any visible key to use a collision-proof explicit name and to carry the
classed non-URL value, but leaves the default at "hidden or explicit" (`KJ-O7`,
`contracts/key-join-contracts.md:244-247`). The default output schema does
**not** include the comparison key. A `key_name` argument defaults to `NULL`
(hidden); supplying a **non-`NULL` unique scalar string** opts into exposing one
column of the classed comparison-key value under that name. If the requested
`key_name` collides with any output column name it is an **early error**, never
a silent rename — consistent with D-F's no-silent-repair rule and P3.1 D-D's
"collision-proof explicit name."

### D-H. KJ-O8 — type restoration and zero-row prototypes

**Decision: results are constructed from `x`'s row-sliced prototype, and every
zero-row/no-match result carries the complete typed would-be output schema.**
P3.1 chooses an independent rurl join contract but fixes neither the
data-frame-subclass/attribute restoration strategy nor the exact empty-result
prototype (`KJ-O8`, `contracts/key-join-contracts.md:248-252`):

1. **Restoration by construction, not by blind copy.** The result is built by
   **row-slicing `x`'s prototype** (`x[integer(0), ]`-style reconstruction) so
   that `x`'s data-frame subclass and its own attribute-preservation behavior
   follow **`x`'s own subsetting/reconstruction contract**. Arbitrary
   non-column attributes are **not** blindly copied across; whatever `x`'s class
   preserves under subsetting is what the result preserves. `y`'s contributed
   columns are appended under the D-F suffix rules with their own types.
2. **Zero-row / no-match prototypes.** Every zero-row or no-match result retains
   the **complete typed would-be output schema** — all `x` columns, all
   contributed `y` columns (including their suffixed names and types), and, when
   exposed, the `key_name` column — each as a length-zero vector of its correct
   type. An empty join result is a fully-typed zero-row frame, never a bare
   `data.frame()` with dropped or untyped columns.

## Rationale

- **G3.K's eight OPEN cells get their single referent.** G3.K recorded each cell
  with an explicit "**Settles at:** … dedicated P3 key/join closure decision"
  (`contracts/key-join-contracts.md:212-253`); this record is that decision, so
  the contract's OPEN rows can flip to SETTLED@P3.2 when G3.K next moves.
- **P3.1 is consumed, not reopened.** Every decision here is a *detail* under a
  P3.1 clause: KJ-O1 under D-B's "explicit standard field," KJ-O2 under D-B's
  host-identity comparison, KJ-O3/O4 under D-D's per-join order and invalid/
  missing defaults, KJ-O5 under D-D's join family, KJ-O6/O7/O8 under D-D's
  "suffix / name repair, zero-row prototypes, stable order" and "key visibility"
  cross-cutting rows. No accepted P3.1 table is altered.
- **The owner spec-exactness mandate drove the one reversal.** KJ-O2 moved from
  the agent's initial "equal" to **distinct** because WHATWG defines URL equality
  over serialized URLs and exempts only certificate comparison from the trailing
  dot; equal-by-default would be a DNS relaxation, not the spec-exact baseline
  the owner mandate requires.
- **Frozen S5 evidence is honored where it forked.** KJ-O3 (right-join order),
  KJ-O4 (anti-join non-keyable retention, "owner confirmation required"), and
  KJ-O6/O8 (suffix/type behavior "not left to incidental `merge()`/
  `data.frame()`") are the exact S5 forks P3.1's prose "pins per S5 matrix" did
  not individually resolve; this record resolves each without letting that phrase
  erase the unmade choice.

## Consequences

- **The G3.K contract can close:** all eight OPEN cells gain an owner decision,
  so G3.K's OPEN rows become SETTLED and the G3.X capstone inherits no unowned
  key/join cell.
- **Join output shape becomes fully specified:** default schema (key hidden),
  suffix repair, empty-result prototypes, and the `by` selector are pinned, so
  G3.7 and G3.4 consume fixed formals.
- **One spec-exact host-identity rule is locked:** the trailing root dot is
  key-significant by default; any collapse is a future explicit versioned policy.
- **A key-policy default is frozen for v3:** `url_key_policy(standard =
  "whatwg")` — safe precisely because no persisted v2 keys exist to reinterpret.
- **New maintenance surface:** the `by`/`key_name`/`suffix` formals and the
  empty-result prototype rules must stay in sync with the six-join matrix; G3's
  contract matrices are the mechanical check.

# P1.2 — v3 authority-state vocabulary

## Decision (PROPOSED)

> **Proposed, not binding.** This record is authored by the agent at
> `state: PROPOSED`. It becomes authoritative only when the owner
> (`github:bart-turczynski`) merges it, at which point the seal procedure
> (P0.1 §Ratification) stamps `ACCEPTED`. Until then nothing here is normative;
> it is the agent's proposed disposition of contradiction **S1-F5** for the
> owner to ratify or adjust. The frontmatter reads `PROPOSED` and
> `accepted_at: pending` because the record never claims an approval that does
> not yet exist.

This record settles the authority-presence vocabulary that **P1.1 Q3 explicitly
deferred** ("stays scoped to C-07 and adopts the general three-valued presence
model only … Destination: a dedicated P1 authority-state decision";
`decisions/P1.1-v3-state-status-model.md:303-306`). It disposes finding
**S1-F5** (`evidence/S1-object-state-vector.md:141-149`) and supplies the
authority vocabulary that G3.3's canonical-state contract left as an explicit
OPEN cell (`contracts/canonical-state-contract.md:111,179-191`). It does **not**
alter any sibling presence axis (path/query/fragment) or the settled
`user`/`password` credential split.

### The contradiction being disposed (S1-F5)

ADR 0012 gives both `host_kind` and `authority_kind` the vocabulary
`{absent, empty, present}` but then defines `authority_kind` operationally as
"whether `//` was present," labelling `foo:///bar` authority-present/host-empty —
which leaves `authority_kind = "empty"` with **no reachable meaning**
(`evidence/S1-object-state-vector.md:143`). The shipped code is internally
inconsistent: `.AUTHORITY_KIND` declares all three values
(`R/parse-state.R:35-47`) while `.authority_kind()` emits only absent/present
and comments call `empty` "reserved" (`R/parse-state.R:92-110`); the general
parser makes **every** `//` row authority-present (`R/parse-state.R:725-746`)
while the RFC `file:` overlay emits authority-empty for the same shape
(`R/parse-state.R:905-919`); and both standard serializers ignore
`authority_kind` entirely, inferring `//` solely from `host_kind`
(`R/parse-phases.R:2521-2534`, `R/parse-phases.R:2570-2576`). The minimal
contradiction: `foo:///bar` and `file:///bar` each contain `//` followed by an
empty authority substring before `/`, yet the generic classifier calls the
first authority-present while the RFC file overlay calls the second
authority-empty (`evidence/S1-object-state-vector.md:147`).

### D-A. Split the authority axis into a delimiter fact and a payload kind

The canonical state records authority presence with **two independent fields**,
retiring the ambiguous single three-valued `authority_kind` enum from the
canonical schema. This is exactly the concrete correction S1-F5 recommends
("separate `authority_delimiter_present: logical` from
`authority_payload_kind: empty|present`, then retain independent `host_kind`";
`evidence/S1-object-state-vector.md:149`).

1. **`authority_delimiter_present: logical`.** Records the single observable
   syntactic fact: did the input contain the `//` authority-introducing
   delimiter after the scheme colon? This is decidable from the source string
   without interpretation and is identical for `foo:///bar` and `file:///bar`
   (both `TRUE`). It is the fact the serializers must consume (D-C).

2. **`authority_payload_kind: {empty, present}`, applicable only when the
   delimiter is present.** When `authority_delimiter_present` is `FALSE`,
   `authority_payload_kind` is **not applicable** and is projected as `NA` — it
   is never forced to a substantive value for a delimiter that does not exist.
   When the delimiter is present:
   - **`empty`** — the authority substring between `//` and the path start
     (`/`, `?`, `#`, or end) is zero-length. Both `foo:///bar` and
     `file:///bar` are delimiter-present + payload-`empty`, and they now agree.
   - **`present`** — the authority substring is non-empty for **any** reason,
     including userinfo-only (`foo://@/bar`), port-only (`foo://:80/bar`), or an
     ordinary host. Payload-`present` does not assert that a host exists; host
     presence is `host_kind`'s job (D-B).

3. **No `empty` value on a compound enum.** The retired three-value
   `authority_kind` conflated a delimiter fact with a payload fact and produced
   an unreachable `empty`. The split makes `empty` reachable and precise: it is
   a payload state under a present delimiter, not a third mutually-exclusive
   sibling of absent/present.

### D-B. `host_kind` stays independent and orthogonal

`host_kind` continues to record host-presence state on its own general
three-valued axis (`{absent, empty, present}`, per P1.1's adopted presence
model), and it is **not** derived from and does **not** derive the authority
fields. The two axes are orthogonal:

| Input | `authority_delimiter_present` | `authority_payload_kind` | `host_kind` |
|---|---:|---|---|
| `http://example.com/` | `TRUE` | `present` | `present` |
| `foo:///bar` | `TRUE` | `empty` | `absent`/`empty` (per host axis) |
| `file:///bar` | `TRUE` | `empty` | `absent`/`empty` (per host axis) |
| `foo://@/bar` (userinfo-only) | `TRUE` | `present` | `empty` |
| `foo://:80/bar` (port-only) | `TRUE` | `present` | `empty` |
| `foo:/bar` (rootless-ish, no `//`) | `FALSE` | `NA` | `absent` |
| `foo:bar` (opaque, no `//`) | `FALSE` | `NA` | `absent` |

The exact `host_kind` value for the empty-payload rows (`absent` vs `empty`) is
governed by the host axis / P4 host slice and G3.H, not by this record; P1.2
fixes only that it is decided **independently** of the authority fields, so the
`foo:///bar`/`file:///bar` disagreement can never recur through authority state.

### D-C. Serializers consume the delimiter fact, never infer it from host

The standard serializers must emit `//` **if and only if**
`authority_delimiter_present` is `TRUE`, and must **not** re-derive `//` from
`host_kind`. This directly repairs the shipped defect where both serializers
inferred `//` from host presence alone (`R/parse-phases.R:2521-2534`,
`R/parse-phases.R:2570-2576`), which cannot distinguish a delimiter-present
empty-authority input from a delimiter-absent one. Emitting the authority
substring content (userinfo, host, port) remains driven by the respective
component states; only the **presence of the `//` introducer** is now bound to
`authority_delimiter_present`.

### D-D. Retire `authority_kind`; retain only as a derived compat projection

The single three-valued `authority_kind` is removed from the canonical schema.
If any downstream consumer requires the legacy name, it is provided **only** as
a **derived, read-only compatibility projection** over the two canonical fields,
never as canonical state and never as a serializer input:

- `authority_delimiter_present == FALSE` → legacy `absent`;
- delimiter present + `authority_payload_kind == empty` → legacy `empty` (now
  reachable and defined);
- delimiter present + `authority_payload_kind == present` → legacy `present`.

The projection exists to avoid a hard break for any reader of the old field; the
two canonical fields are the single source of truth, and the state tests that
currently enforce the two-value "whether `//`" interpretation
(`tests/testthat/test-parse-state.R:75-81`) are revised in the implementation
slice to assert the split fields plus this projection.

### Required fixtures (implementation slice)

The implementation slice must prove all combinations with at least:

- `foo:/bar` — delimiter absent, payload `NA`.
- `foo:bar` — opaque, delimiter absent, payload `NA`.
- `foo:///bar` — delimiter present, payload `empty`.
- `file:///bar` — delimiter present, payload `empty` (agrees with `foo:///bar`).
- `foo://@/bar` — delimiter present, payload `present`, userinfo-only.
- `foo://:80/bar` — delimiter present, payload `present`, port-only.
- an ordinary non-empty host authority (`http://example.com/`) — delimiter
  present, payload `present`, host `present`.

Each fixture asserts the two canonical fields, the independent `host_kind`, the
derived legacy projection, and serializer `//` emission driven by
`authority_delimiter_present`.

## Rationale

- **S1-F5's own concrete correction is adopted verbatim.** The finding names
  two remedies — split the axis, or keep the three-value enum and "define every
  value operationally and prove all combinations"
  (`evidence/S1-object-state-vector.md:149`). The split is chosen because it is
  strictly less work (no need to manufacture a reachable meaning for a
  compound-enum `empty`) and because the ambiguity arose precisely from
  overloading one enum with a delimiter fact and a payload fact.
- **P1.1 Q3 is discharged.** P1.1 deferred exactly this vocabulary to "a
  dedicated P1 authority-state decision" (`P1.1:303-306,314-315`); this record
  is that decision, on the P1 tier, under the same owner authority.
- **G3.3's open cell gets its referent.** The canonical-state contract's
  `authority_kind` row and Open-cell entry are explicitly waiting on "the
  deferred sibling P1 authority-state decision … this contract adopts that
  record's vocabulary once accepted"
  (`contracts/canonical-state-contract.md:190-191`). On acceptance G3.3 binds
  the two split fields and closes the cell.
- **The identity/presentation discipline is upheld.** Making the serializer
  consume a recorded syntactic fact (delimiter present) rather than infer it
  from a derived component (host) is the same identity-before-presentation
  posture ADR 0011/0012 and P3.1 apply elsewhere: the object records what was
  observed; presentation reads that record.

  since it never defined a reachable `authority_kind = empty`.

## Consequences

- **`foo:///bar` and `file:///bar` can never disagree through authority state
  again:** both are delimiter-present + payload-`empty`, and host presence is a
  separate axis.
- **`authority_kind = empty` becomes reachable and defined** — as a payload
  state under a present delimiter — instead of an unreachable third enum value.
- **Serialization becomes faithful for empty-authority inputs:** the serializer
  emits `//` from a recorded fact, so a delimiter-present empty authority is no
  longer indistinguishable from a delimiter-absent input.
- **A small compatibility surface is added:** the derived `authority_kind`
  projection must stay in sync with the two canonical fields; G3's contract
  matrices are the mechanical check.
- **Downstream G3.3/G3.5/G3.H inherit a settled vocabulary** to bind instead of
  an OPEN cell.

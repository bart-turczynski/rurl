# P0.6 — G3 closure-input scope: the gate pins the invariant, not the roster

## Decision (PROPOSED)

> This record is the agent's **proposed** disposition, offered for the owner to
> ratify, reject, or adjust. Nothing here is binding until the owner merges it
> (P0.1 §4).

### 1. The defect

§7 G3 exit criterion 1 reads:

> The artifact set in §6 exists and contains no unowned cells.

That is a **universally quantified property** over the public surface. The G3
acceptance enforced it by recording a byte hash of
`contracts/public-surface-closure.md` in its `## Inputs`. But that file contained
two different kinds of thing:

- the **invariant** — the ownership rule, the owning-contract legend, the citation
  discipline, the `PSC-O1..O5` open-cell grouping; and
- the **roster** — one row per public-surface cell, plus the arithmetic describing
  how many there are.

Hashing them as one blob means the gate pins the *extension* of the property
rather than the property. Adding an export edits the roster, drifts the hash, and
reopens contract-matrix closure — even though the invariant is untouched and the
new row **satisfies** it. `get_parse_verdicts()` (PR #281) demonstrated this: it
cost a dedicated seal PR (#284), a superseding gate record, three chained re-pins,
and a window in which `main` was red.

The cost was not one-off. `serialize_url` (RURL-zthbwebb), the key/join family of
eight exports (RURL-mihbyjsr), and `format_url` (RURL-nyjnplyh) were each on
course to reopen G3 the same way — one re-acceptance per PR that grows the
surface, somewhere between three and ten more, each for an owned, SETTLED row.

### 2. The decision

**Artifact 4 is two files.**

| half | file | pinned by | changes when |
|---|---|---|---|
| invariant | `contracts/public-surface-closure.md` | G3 acceptance `## Inputs` (unchanged mechanism) | the ownership model changes |
| roster | `contracts/public-surface-disposition.md` | `manifest.artifacts[]` | the public surface changes |

The invariant states five clauses, `I1`–`I5`, quoted here as the normative text:

- **I1 — Population is derived, never transcribed.** The set of public-surface
  cells is exactly: every `export(...)` line in `NAMESPACE`, every entry of
  `.spu_result_fields`, the curl-dependency surfaces, and the migration surface.
  No count of them is normative anywhere in artifact 4.
- **I2 — Every cell is owned.** Each cell has exactly one roster row naming an
  owning contract drawn from the legend. A cell with no row, a row with no cell,
  and a row naming a contract outside the legend are each violations.
- **I3 — Every disposition is SETTLED or OPEN, with a citation that resolves.**
  `SETTLED` cites the accepted decision its owning contract projects. `OPEN` cites
  an open-cell ID **that exists in the contract it names**, or a named downstream
  artifact.
- **I4 — No open question is invented in artifact 4.**
- **I5 — The Stage-A internals stay out.**

**What reopens G3, and what does not.** A roster change that keeps I1–I5 true
changes no fact the gate-pinned file asserts and therefore **reopens nothing**. A
change to I1–I5, to the legend, or to the agreement section is a change to the
ownership model and **reopens G3** exactly as the existing reopening rule
prescribes. Nothing about the reopening mechanism itself changes: it is still a
superseding gate record, never an edit to an accepted record's hashes.

### 3. Why this is not a weakening

The objection recorded on `RURL-oygqsykd` is that a byte hash is exactly
tamper-evident, while "the discipline holds" is a semantic proxy that could be
satisfied by a contract that drifted in a way the proxy does not model. It
deserves a direct answer, because it is the only real argument against this
change.

**First, what the hash was actually buying.** Before this record the closure
validator asserted three things about the roster: that the export table's *row
count* equalled the NAMESPACE export count, that the field table had 18 rows, and
that the bijection summed to 52. It did **not** check that the export row *names*
matched NAMESPACE (only the count — a renamed row passed), that a row's owning
contract was one of the ten, that a `SETTLED` row cited any decision, or that an
`OPEN` row's cited open-cell ID existed anywhere at all.

**Second, what replaces it.** I1–I5 are enforced by `validate-records.R` on every
run, by name and by resolution rather than by cardinality. The four checks listed
above as absent are now present. This is a **strictly stronger** statement about
the roster than the pin it replaces, on precisely the dimensions artifact 4
claims.

**Third, tamper-evidence is retained, not traded.** The roster is byte-pinned in
`manifest.artifacts[]`, which `validate-manifest.R` verifies on every run in
strict mode. The change is *where* the volatile artifact is pinned — a manifest
pin is a one-line update inside the PR that changes the surface, whereas a gate
`## Inputs` pin can only be updated by a superseding acceptance record. Nothing
becomes unpinned.

**Fourth, the split is enforced structurally.** `validate-records.R` fails if a
roster table appears in the gate-pinned invariant, so the halves cannot be
quietly re-merged by a future edit, restoring the cascade by accident.

### 4. What this record does not do

- It does **not** relax any contract cell, or change any cell's SETTLED/OPEN
  disposition. Every roster row is carried across verbatim.
- It does **not** add or remove public surface. `NAMESPACE` and
  `.spu_result_fields` are untouched; no package code changes.
- It does **not** alter G3's exit criteria, the reopening rule, or the
  supersession mechanics accepted at `G3-acceptance-2`.
- It does **not** change the claim population of the G4 traceability map. The 64
  artifact-4 claims move from prefix `TR-PS-*` to `TR-PSD-*` and are otherwise
  identical; the census total is byte-identical at 480 claims before and after.
- It does **not** touch the G1 inventory register's substance.

### 5. Consequences

- One final G3 re-acceptance is required, because moving the roster out changes
  the invariant's bytes. That is the price of the buy-out and it is paid once, in
  the seal PR that follows this record's merge (P0.1 §Ratification phase 3).
- The stale-count class of defect is retired. The prose counts that survived the
  51→52 growth — `29 exports` in three separate places of the closure contract,
  including its `completion_rule` envelope field — are removed rather than
  corrected, because a transcribed count is a stale fact waiting to happen. The
  validator's own literals (`30L`, `18L`, `52L` in two places) are removed for the
  same reason.
- Future surface work — `serialize_url`, the key/join family, `format_url` — lands
  as a single PR each, with no seal PR, no superseding gate record, and no
  red-`main` window.
